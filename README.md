# Закулисье Ходынки

Браузерный хоррор от первого лица на JavaScript + Three.js. Найди свою квартиру №47 в лабиринте жилых коридоров. От монстра можно спрятаться в боковых квартирах и наблюдать за ним через глазок.

## Запуск

Node.js 22.12+.

Игра с общим лидербордом:

```sh
npm install
npm run build
npm start
```

Открыть http://127.0.0.1:4180/. Для разработки оставить сервер запущенным и в отдельном терминале запустить `npm run dev`: Vite перенаправляет `/api` на сервер 4180.

```sh
npm install
npm run dev
```

Открыть адрес из терминала, обычно http://127.0.0.1:5173. Игра запускается через HTTP, не двойным кликом по index.html.

## Управление

- WASD — движение; мышь — обзор, русская раскладка работает.
- Shift — бег; выносливость восстанавливается при ходьбе и в укрытии.
- E — открыть/закрыть торцевую дверь, войти в боковую квартиру, выйти из укрытия.
- Q — посмотреть в глазок / отойти от него, когда прячешься.
- F — фонарик; Esc — пауза с остановкой симуляции и голоса.
- Если захват мыши недоступен: удерживать левую кнопку мыши или поворачивать стрелками ← →.
- Для сенсорного экрана есть кнопки и обзор движением пальца по правой части экрана. Основная платформа — компьютер с мышью и клавиатурой.

## Правила прототипа

Каждая новая игра создаёт связный лабиринт с девятью узлами и восемью длинными коридорами. Повороты случайны, но уже открытые пути сохраняются до конца забега. В конце коридоров — открываемые двери. Целевая квартира №47 всегда существует и доступна; предметы для открытия не нужны.

Боковые квартиры служат укрытиями. Вход автоматически переносит игрока в маленькую прихожую и закрывает дверь. Глазок показывает настоящий коридор с круглой маской и оптическим искажением. Если монстр заметил вход, он подходит к этой двери и стучит, затем уходит. В этом прототипе он не взламывает квартиру; опасно выйти, пока он рядом. Сквозь закрытые торцевые двери монстр не видит, но умеет открыть их с небольшой задержкой.

Первые 12 секунд монстр не активен. После этого он появляется за поворотом: вне прямой видимости даже при открытых дверях, не ближе 14 метров и минимум в девяти клетках пути. Первая секция исключена из точек появления. Если подходящей точки нет, появление откладывается. Он патрулирует коридоры, замечает игрока в прямой видимости, слышит бег и преследует последнюю известную позицию. Настройка «Без монстра» позволяет спокойно исследовать уровень. При поражении используется присланный злой ракурс; забег можно начать заново.

## Изображения

Все четыре пользовательских ракурса подключены как прозрачный 2D-билборд в 3D-пространстве. Вид спереди, сзади и сбоку выбирается по направлению монстра относительно камеры. Боковой ракурс зеркалируется для второй стороны. Злая эмоция появляется при близкой погоне и нападении.

Меню называется «Закулисье Ходынки» и содержит три пункта: Новая игра, Настройки, Управление. Для него создан отдельный фон по пользовательскому референсу. Источники, настройки импорта и точный промпт: [ASSETS.md](ASSETS.md).

## Реплики и звук

В меню играет записанная атмосферная музыка «Tragic ambient main menu». Браузер пробует включить её сразу; если автозапуск запрещён, музыка включается первым кликом или клавишей. Кнопка в меню показывает реальное состояние звука. Шаги используют шесть записей по твёрдому полу с вариациями темпа и громкости. Вместо непрерывного синтезированного шума — тихая запись люминесцентной лампы, затихающая вдали от светильников и в укрытии. Открытие и закрытие дверей используют записи, включая автоматическое закрытие укрытия и двери монстра. Стук и дыхание монстра пока синтезируются. Скример — MP3, извлечённый из пользовательского видео. Он доигрывает на экране поражения; возврат в меню и новый забег останавливают его. В укрытии слышно сердцебиение. Громкость регулируется в настройках.

Присланные MP3 включены в сборку: «за дверью» с вероятностью 40% при входе в укрытие; при появлении монстра в поле зрения с вероятностью 50% выбирается «шот» или «отъебись». Между событийными репликами минимум 22 секунды, одновременно голоса не играют.

Настройки → Голос персонажа → Добавить реплики. MP3/WAV/OGG декодируются локально, по одному файлу до 30 МБ. Дополнительная случайная реплика играет каждые 20–35 секунд активной игры. В укрытии дополнительные реплики отключены, но может прозвучать «за дверью». Вход в укрытие и пауза останавливают текущую реплику. Добавленные файлы остаются в памяти вкладки до перезагрузки, настройки сохраняются локально.

## Вступление и засады — v0.3

Новая игра начинается с трёх согласованных текстовых слайдов с плавным появлением, затем воспроизводится пользовательское видео длиной 32 секунды. Есть кнопки перехода дальше и пропуска. Игровой таймер запускается после вступления. Победа открывает два согласованных финальных слайда на тёмном фоне.

После проверки укрытия монстр патрулирует коридоры поблизости. Он может сам зайти в свободную квартиру и устроить засаду: вход в занятую квартиру заканчивается нападением, а при приближении по коридору монстр может выйти из неё. Текущая квартира игрока и целевая №47 исключены из выбора засады. Дыхание за дверью помогает заметить опасность. Когда замеченный монстр преследует игрока, освещение плавно краснеет.

## Проверки и сборка

```sh
npm test
npm run test:browser
npm run test:media
npm run test:sound
npm run build
npm run preview
```

Для test:browser нужен работающий dev-сервер на порту 5173 и установленный Google Chrome. Проверка использует отдельный headless-профиль: меню, PNG, декодирование WAV, движение, фонарь, пауза, укрытие, живой глазок, маршрут домой через двери, победа, поражение и повторный запуск. Снимки — в output/playwright/.

Модульные тесты проверяют связность 50 лабиринтов, достижимость квартиры, двери и коллизии, видимость, выбор ракурса и поведение монстра у укрытия.

test:media использует тот же dev-сервер и Chrome: проверяет слайды, реальное воспроизведение MP4 и переход в игру, декодирование всех трёх MP3, интервалы реплик, красное освещение, нападение в квартире и финал.

Готовая статическая сборка — dist/. Игровую часть можно разместить статически, но общий лидерборд требует Node-сервер ниже. Публичная публикация ещё не выполнена. Текстуры и картинки включены в сборку. Cormorant Garamond и PT Sans подгружаются из Google Fonts, при отсутствии сети используются системные шрифты.

## Код

- src/level.js — генерация лабиринта, двери, коллизии, поиск пути и выбор ракурса.
- src/monster.js — патруль, погоня и проверка укрытия.
- src/world.js — 3D-коридоры, свет, анимация дверей, билборд, рендер глазка.
- src/main.js — управление, состояния игры, укрытия, меню, голосовые события.
- src/audio.js — Web Audio и загрузка своих реплик.
- src/cinematics.js — согласованные тексты, смена слайдов и видеокатсцена.
- src/style.css — интерфейс и фон главного меню.

Только dev-сборка предоставляет window.__game для воспроизводимых проверок. В production этот интерфейс удалён.

## Изменения v0.4

Доступные укрытия редеют с глубиной лабиринта: 3 → 2 → 1. Остальные двери остаются на месте, но заперты; подсказка показывает это перед входом. Своя квартира всегда открывается. Планировка и состояние дверей сохраняются при возвращении назад. Монстр быстрее патрулирует и преследует, слышит бег до 30 метров, помнит игрока 14 секунд и чаще готовит засаду.

Фон меню плавно двигается от мыши. При системной настройке reduced motion эффект отключается. test:sound проверяет декодирование четырнадцати аудиофайлов, ненулевой сигнал музыки и шагов на выходе микшера, тихий фон, запертые квартиры и параллакс. Проверка сигнала не заменяет оценку звучания на пользовательских наушниках. Источники аудио и лицензии — в ASSETS.md.

## Исправления v0.4.1

Убрана мгновенная встреча за первой дверью: безопасность появления проверяется относительно текущего положения игрока, включая быстрый проход через первую дверь. Тесты охватывают 100 лабиринтов и обе стороны первой двери, а также подтверждают, что после начальной паузы монстр продолжает находить открыто стоящего игрока.

## Частота встреч и свет v0.4.2

Начальная пауза сокращена до 12 секунд при сохранении дистанции появления от 14 метров и проверки видимости сквозь открытые двери. Вне укрытия монстр ищет текущую позицию игрока, обновляя цель каждые 1,5 секунды; около занятого укрытия патрулирует небольшую область. Скорость поиска 3,5 м/с, погони 4,2 м/с. Для засад выбираются только квартиры в пределах шести клеток пути от монстра, чтобы он не уходил в долгий обход.

Гул и фонарик сохранены. Интенсивность ламп снижена с 6 до 4,7, общий свет с 1,05 до 0,72. Проверка движущегося к дому игрока на 50 лабиринтах обнаруживает первую встречу до 20-й секунды; безопасность появления проверяется отдельно.

## Ник, таймер и общий рейтинг v0.5

В главном меню есть поле ника (до 20 символов) и «Лучшие побеги». Пустой ник заменяется на Гость с коротким идентификатором. Ник и идентификатор игрока сохраняются в браузере. Сервер хранит лучший результат каждого идентификатора и показывает топ-50 по возрастанию времени. Одинаковые ники разрешены, аккаунтов и авторизации пока нет; другой браузер считается другим игроком.

Таймер показывает минуты, секунды и сотые, считает реальное активное время игры независимо от ограничения шага симуляции. Пауза, катсцены и финальные слайды исключены; укрытие учитывается. Результат отправляется только при входе в квартиру 47. Поражения не записываются. Если режим «Без монстра» был включён хотя бы один раз в забеге, результат исключается. Недоступность сервера явно отображается, локальные результаты не выдаются за общий рейтинг.

`server/index.js` раздаёт dist и API с одного адреса; поддерживает Range для видео. `server/leaderboard.js` хранит данные в `data/leaderboard-v1.json`, записывает через временный файл и переименование. Папка data исключена из Git. Для размещения в интернете нужен один Node-процесс и постоянный диск: переменные `PORT`, `HOST=0.0.0.0`, `LEADERBOARD_FILE` задают порт, сетевой интерфейс и файл рекордов. Не запускать несколько процессов, записывающих один JSON. Публичное размещение ещё не выполнено.

Это рейтинг прототипа: сервер выдаёт одноразовый билет забега, проверяет формат и верхнюю границу времени по своим часам, однако клиент сообщает факт финиша и игровое время. Полноценной защиты от изменения клиентского кода нет. Для соревновательного релиза потребуется серверная проверка прохождения.

Проверки: `npm test`, `npm run test:leaderboard`. Последняя запускает отдельное тестовое хранилище, проверяет настоящий API, две независимые браузерные сессии, сохранение ника, паузу/финиш таймера, исключение мирного режима и перемотку видео. Нужны Chrome и dev-сервер 5173. Тестовые результаты не попадают в основную таблицу.
